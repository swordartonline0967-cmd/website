# 01. サイトを公開する手順

このサイトは「GitHub Pages（ギットハブ ページズ）」という**無料**のサービスで公開できます。
作業はすべてブラウザ（パソコン推奨）で、GitHub の画面をクリックしていくだけです。所要時間は20分ほどです。

> 💡 画面のボタン名は英語です。この説明書では「**Settings**（設定）」のように、英語の表示名と意味を並べて書いています。

---

## 全体の流れ

1. ブランチ名を `main` にする（最初の1回だけ）
2. GitHub Pages を有効にする（最初の1回だけ）
3. 公開処理を実行して、10分ほど待つ
4. 公開されたサイトを確認する

---

## 1. ブランチ名を `main` にする（最初の1回だけ）

いま、サイトのプログラムは `claude/modest-maxwell-j0xlje` という名前の「ブランチ」（作業場所）に保存されています。
自動公開は `main` という名前のブランチを見て動くので、名前を `main` に変えます。

> 🙋 **一番かんたんな方法**：Claude に「main ブランチを作って」と頼んでください。以下の手作業は不要になります（その場合は手順 1-4 の「Default branch を main に切り替える」だけ行ってください）。

手作業で行う場合：

1. ブラウザで https://github.com/swordartonline0967-cmd/website を開きます
2. 上のメニューの右のほうにある「**⚙ Settings**」（設定）をクリックします
3. 左のメニューで「**General**」（全般）が選ばれていることを確認します
4. 「**Default branch**」（標準のブランチ）という欄に `claude/modest-maxwell-j0xlje` と表示されています。
   その右にある **鉛筆マーク（✏️ Rename branch）** をクリックします
5. 入力欄を `main` に書き換えて「**Rename branch**」をクリックします

これで、ブランチ名が `main` になりました。

---

## 2. GitHub Pages を有効にする（最初の1回だけ）

1. 同じく「**⚙ Settings**」の画面で、左のメニューから「**Pages**」をクリックします
2. 「**Build and deployment**」（ビルドと公開）の欄にある「**Source**」（公開の方法）のプルダウンをクリックし、
   「**GitHub Actions**」を選びます（選ぶだけで自動保存されます）

> ⚠ 「リポジトリを Public（公開）にしてください」という表示が出た場合：
> 無料プランの GitHub Pages は、リポジトリが **Public（公開）** でないと使えません。
> 「Settings」→「General」の一番下「**Danger Zone**」→「**Change visibility**」→「**Change to public**」で公開にできます。
> （プログラムやデータが誰でも見られる状態になりますが、パスワードなどの秘密情報は含まれていないので問題ありません）

---

## 3. 公開処理を実行する

ブランチを `main` にした時点で自動的に始まっていることもあります。念のため手動でも実行しておきましょう。

1. 上のメニューの「**▶ Actions**」をクリックします
   - 「I understand my workflows, go ahead and enable them」という緑のボタンが出たら、それをクリックします
2. 左の一覧から「**サイトを公開（GitHub Pages）**」をクリックします
3. 右側の「**Run workflow**」（実行）ボタン → ブランチが `main` になっていることを確認 → 緑の「**Run workflow**」をクリック
4. 一覧に新しい行が現れます。黄色い丸（実行中）が **緑のチェック ✓** になれば完了です（10分前後かかります）
   - **赤い ✗** になった場合は失敗です。その行をクリックすると原因が表示されるので、画面の文字をコピーして Claude に「このエラーを直して」と伝えてください

---

## 4. 公開されたサイトを確認する

次のURLをブラウザで開きます。

**https://swordartonline0967-cmd.github.io/website/**

（「Settings」→「Pages」の画面の上部にも「Your site is live at …」とURLが表示されます）

🎉 これで公開完了です！ スマホでも開いてみてください。

---

## 公開後の自動処理について

設定はすべて済んでいるので、以下は**何もしなくても自動で行われます**。

| いつ | 何が起きる |
| --- | --- |
| `main` ブランチのファイルが変更されたとき | サイトが作り直されて公開される（約10分） |
| 毎日 朝5時（日本時間） | サイトを作り直す（「今日は何の日」「発売予定」を最新にするため） |
| 毎週 月曜 朝3時（日本時間） | Wikipedia / Wikidata から新しいソフト情報を取り込んで公開 |

## （おすすめ）独自ドメインを使う

`https://swordartonline0967-cmd.github.io/website/` のままでも使えますが、アフィリエイトで収益化するなら
**独自ドメイン（例: `https://www.gamesoft-taizen.com`）の取得をおすすめします。**

- アフィリエイトの審査で信頼されやすい
- 後で公開先（GitHub Pages → Cloudflare など）を変えても、URLが変わらないので検索順位が引き継がれる

### 手順の概要

1. ドメインを買う（年1,000〜2,000円程度）
   例: [Cloudflare Registrar](https://www.cloudflare.com/ja-jp/products/registrar/)、お名前.com、ムームードメイン、Xserverドメイン など
2. GitHub の「Settings」→「Pages」→「**Custom domain**」に、買ったドメイン（例: `www.gamesoft-taizen.com`）を入力して「Save」
3. ドメインを買ったサービスの「DNS設定」で、次の設定を追加する
   - 種類 `CNAME`、名前 `www`、値 `swordartonline0967-cmd.github.io`
4. 数分〜数時間後に GitHub の画面で確認が完了したら、「**Enforce HTTPS**」にチェックを入れる
5. `src/config/site.ts` の `url` も新しいドメインに書き換えておく（例: `url: 'https://www.gamesoft-taizen.com',`）

自動公開の処理は新しいドメインを自動で読み取るので、ほかの設定変更は不要です。

## 収益化が本格化したら：Cloudflare への移行（任意・月額約750円）

GitHub Pages の利用規約では、「商取引を主な目的とするサイト」の公開は認められていません。
このサイトはゲーム情報のデータベースが主目的ですが、**アフィリエイト収入が本格的に発生してきたら、商用利用が認められている Cloudflare（クラウドフレア）への移行をおすすめします。**

- Cloudflare の無料プランは「1サイト2万ファイルまで」のため、このサイト（約5.7万ファイル）には **Workers Paid プラン（月額5ドル）** が必要です
- 設定ファイル（`wrangler.jsonc`）は用意済みです

### 手順の概要

1. [Cloudflare](https://dash.cloudflare.com/sign-up) のアカウントを作る
2. 管理画面の「**Workers & Pages**」→ プラン画面で「**Workers Paid**」（月額5ドル）に申し込む
3. 「Workers & Pages」→「**Create**」（作成）→「**Import a repository**」（リポジトリから作成）→ GitHub と連携し、`website` リポジトリを選ぶ
4. 次のように入力して保存・デプロイする
   - プロジェクト名: `game-database-site`
   - Build command（ビルドコマンド）: `npm run build`
   - Deploy command（デプロイコマンド）: `npx wrangler deploy`
   - Build variables（ビルド用の環境変数）: 名前 `SITE_URL`、値 `https://あなたのドメイン`
5. 表示された `〜.workers.dev` のURLで表示を確認する
6. 独自ドメインを Cloudflare 側につなぎ替える（プロジェクトの「Settings」→「Domains & Routes」→「Add」→「Custom domain」）
7. GitHub 側の「Settings」→「Pages」で Custom domain を削除し、「Actions」で「サイトを公開（GitHub Pages）」を「Disable workflow」（停止）にする

> Cloudflare の画面の名前は変わることがあります。わからなくなったら Claude に「Cloudflareに移行したい」と相談してください。

## 困ったときは

| 症状 | 対処 |
| --- | --- |
| URLを開くと 404 になる | 手順3の処理が緑のチェックになっているか確認。完了直後は数分待ってから再読み込み |
| デザインが崩れている | 「Settings」→「Pages」の Source が「GitHub Actions」になっているか確認 |
| 「データを自動更新」が失敗する（権限エラー） | 「Settings」→「Actions」→「General」→「Workflow permissions」を「**Read and write permissions**」にして「Save」 |
| その他のエラー | Actions の画面のエラー文をコピーして、Claude に貼り付けて相談 |
