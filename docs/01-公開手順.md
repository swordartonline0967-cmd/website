# 01. サイトを公開する手順

作業はすべてブラウザ（パソコン推奨）で、GitHub などの画面をクリックしていくだけです。

> 💡 画面のボタン名は英語です。この説明書では「**Settings**（設定）」のように、英語の表示名と意味を並べて書いています。
> 🙋 わからなくなったら、画面の文字をコピーして Claude に「ここからどうすればいい？」と聞いてください。

---

## 0. まず「公開方法」を選ぶ

あなたのリポジトリ（プログラムの保存場所）は現在 **非公開（Private）** になっています。
公開方法は次の2つから選べます。

|  | **A. GitHub Pages** | **B. Cloudflare（クラウドフレア）** |
| --- | --- | --- |
| 費用 | **無料** | 月額5ドル（約750円）の Workers Paid プラン |
| リポジトリ | **公開（Public）に変更が必要**（誰でもプログラムを見られる） | **非公開のまま** でOK |
| アフィリエイト（商用利用） | 規約上は「商取引が主目的のサイト」は不可。情報サイトなので始める分には問題になりにくいが、本格的な収益化には不向き | **OK** |
| 表示速度（日本） | 普通 | 速い |
| 設定の手間 | 少ない（10分） | やや多い（アカウント作成・カード登録、20分） |
| おすすめの人 | **まず無料で公開してみたい** | **最初から収益化を前提にしたい** |

- **迷ったら A で始めて、収入が出始めたら B に移る** のがおすすめです。移行してもサイトの中身はそのまま使えます
- A でリポジトリを公開にすると、サイトのプログラムやデータを他の人も見られるようになります（パスワードなどの秘密情報は入っていません）。
  「サイトの作りを真似されたくない」場合は B を選んでください
- どちらを選んでも、先に **「1. ブランチ名を main にする」** を行ってください

> ℹ このサイトは約5.7万ファイルあるため、Cloudflare の **無料プラン（2万ファイルまで）では公開できません**。B を選ぶ場合は有料プラン（月5ドル）が必要です。

---

## 1. ブランチ名を `main` にする（共通・最初の1回だけ）

いま、サイトのプログラムは `claude/modest-maxwell-j0xlje` という名前の「ブランチ」（作業場所）に保存されています。
自動公開は `main` という名前のブランチを見て動くので、名前を `main` に変えます。

1. ブラウザで https://github.com/swordartonline0967-cmd/website を開きます
2. 上のメニューの右のほうにある「**⚙ Settings**」（設定）をクリックします
3. 左のメニューで「**General**」（全般）が選ばれていることを確認します
4. 「**Default branch**」（標準のブランチ）という欄に `claude/modest-maxwell-j0xlje` と表示されています。
   その右にある **鉛筆マーク（✏️ Rename branch）** をクリックします
5. 入力欄を `main` に書き換えて「**Rename branch**」をクリックします

これで、ブランチ名が `main` になりました。

## A. GitHub Pages で公開する（無料）

### A-1. リポジトリを公開（Public）にする

1. 「**⚙ Settings**」→ 左メニュー「**General**」の画面を一番下までスクロールします
2. 赤い枠の「**Danger Zone**」（注意が必要な操作）にある「**Change repository visibility**」の「**Change visibility**」をクリック
3. 「**Change to public**」を選び、確認画面の指示に従って進めます（リポジトリ名の入力を求められたら `swordartonline0967-cmd/website` と入力）

### A-2. GitHub Pages を有効にする

1. 「**⚙ Settings**」の画面で、左のメニューから「**Pages**」をクリックします
2. 「**Build and deployment**」（ビルドと公開）の欄にある「**Source**」（公開の方法）のプルダウンをクリックし、
   「**GitHub Actions**」を選びます（選ぶだけで自動保存されます）

### A-3. 公開処理を実行する

1. 上のメニューの「**▶ Actions**」をクリックします
   - 「I understand my workflows, go ahead and enable them」という緑のボタンが出たら、それをクリックします
2. 左の一覧から「**サイトを公開（GitHub Pages）**」をクリックします
3. 右側の「**Run workflow**」（実行）ボタン → ブランチが `main` になっていることを確認 → 緑の「**Run workflow**」をクリック
4. 一覧に新しい行が現れます。黄色い丸（実行中）が **緑のチェック ✓** になれば完了です（10分前後かかります）
   - **赤い ✗** になった場合は失敗です。その行をクリックすると原因が表示されるので、画面の文字をコピーして Claude に「このエラーを直して」と伝えてください

### A-4. 公開されたサイトを確認する

次のURLをブラウザで開きます。

**https://swordartonline0967-cmd.github.io/website/**

（「Settings」→「Pages」の画面の上部にも「Your site is live at …」とURLが表示されます）

🎉 これで公開完了です！ スマホでも開いてみてください。

### A を選んだ場合の自動処理

| いつ | 何が起きる |
| --- | --- |
| `main` ブランチのファイルが変更されたとき | サイトが作り直されて公開される（約10分） |
| 毎日 朝5時（日本時間） | サイトを作り直す（「発売予定」などを最新にするため） |
| 毎週 月曜 朝3時（日本時間） | Wikipedia / Wikidata から新しいソフト情報を取り込んで公開 |

## B. Cloudflare で公開する（月額約750円・リポジトリは非公開のまま）

設定ファイル（`wrangler.jsonc`）は用意済みです。

1. [Cloudflare の登録ページ](https://dash.cloudflare.com/sign-up) でアカウントを作ります（メールアドレスとパスワード）
2. 管理画面の左メニュー「**Workers & Pages**」を開き、プラン（Plans）の画面から「**Workers Paid**」（月額5ドル）に申し込みます
   （クレジットカードの登録が必要です）
3. 「Workers & Pages」の画面で「**Create**」（作成）→「**Import a repository**」（リポジトリから作成）を選びます
4. 「GitHub と接続」を求められたら許可し、`website` リポジトリへのアクセスを許可します
5. 一覧から `website` を選び、次のように入力します
   | 項目 | 入力する内容 |
   | --- | --- |
   | Project name（プロジェクト名） | `game-database-site` |
   | Production branch（本番ブランチ） | `main` |
   | Build command（ビルドコマンド） | `npm run build` |
   | Deploy command（デプロイコマンド） | `npx wrangler deploy` |
6. 「**Save and Deploy**」（保存して公開）をクリックします。5〜10分ほどで完了します
7. 表示された `https://game-database-site.〇〇.workers.dev` のURLを開いて表示を確認します
8. GitHub の「▶ Actions」→ 左の「**サイトを公開（GitHub Pages）**」→ 右上の「…」→「**Disable workflow**」（停止）をクリックします
   （B では GitHub Pages を使わないため。止めないと毎日エラーのお知らせが届きます）
9. 公開URLを `src/config/site.ts` の `url` に書いておきます（例: `url: 'https://game-database-site.〇〇.workers.dev',`）

### B を選んだ場合の自動処理

- `main` ブランチのファイルが変更されるたびに、Cloudflare が自動でサイトを作り直して公開します
- 毎週月曜の「データ自動更新」でソフト情報に変更があれば、その保存をきっかけに自動で公開されます

> Cloudflare の画面の名前は変わることがあります。わからなくなったら Claude に「Cloudflareで公開したい」と相談してください。

## （おすすめ）独自ドメインを使う

アフィリエイトで収益化するなら、**独自ドメイン（例: `https://www.gamesoft-taizen.com`）の取得をおすすめします。**

- アフィリエイトの審査で信頼されやすい
- 後で公開先（A → B など）を変えても、URLが変わらないので検索順位が引き継がれる

### 手順の概要

1. ドメインを買う（年1,000〜2,000円程度）
   例: [Cloudflare Registrar](https://www.cloudflare.com/ja-jp/products/registrar/)、お名前.com、ムームードメイン、Xserverドメイン など
2. 公開先ごとの設定
   - **A（GitHub Pages）の場合**：GitHub の「Settings」→「Pages」→「**Custom domain**」にドメイン（例: `www.gamesoft-taizen.com`）を入力して「Save」。
     ドメインを買ったサービスのDNS設定で「種類 `CNAME`、名前 `www`、値 `swordartonline0967-cmd.github.io`」を追加。
     確認が完了したら「**Enforce HTTPS**」にチェック
   - **B（Cloudflare）の場合**：Cloudflare のプロジェクト画面「Settings」→「Domains & Routes」→「Add」→「Custom domain」でドメインを追加
3. `src/config/site.ts` の `url` を新しいドメインに書き換えておく（例: `url: 'https://www.gamesoft-taizen.com',`）

## 困ったときは

| 症状 | 対処 |
| --- | --- |
| URLを開くと 404 になる | 公開処理が緑のチェックになっているか確認。完了直後は数分待ってから再読み込み |
| デザインが崩れている（A） | 「Settings」→「Pages」の Source が「GitHub Actions」になっているか確認 |
| 「Pages が使えません」「アップグレードが必要」と出る（A） | リポジトリが非公開のままです。手順 A-1 で Public にしてください |
| 「データを自動更新」が失敗する（権限エラー） | 「Settings」→「Actions」→「General」→「Workflow permissions」を「**Read and write permissions**」にして「Save」 |
| その他のエラー | Actions（または Cloudflare）の画面のエラー文をコピーして、Claude に貼り付けて相談 |
