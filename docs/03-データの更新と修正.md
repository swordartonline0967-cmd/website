# 03. ソフト情報の更新と修正

## データはどこから来ているか

| データ | 取得元 | ライセンス |
| --- | --- | --- |
| ソフトのタイトル・日本での発売日・発売元・備考 | Wikipedia日本語版「〇〇のゲームタイトル一覧」（機種ごと） | CC BY-SA 4.0 |
| ジャンル・開発元（一部） | Wikidata | CC0 |
| ゲーム機の情報・説明文 | このサイト独自（`data/platforms.json`） | — |

取り込んだデータは `data` フォルダにJSON（ジェイソン）という形式で保存され、サイトはそれを読み込んで作られます。

---

## 自動更新（何もしなくてOK）

**毎週月曜 朝3時（日本時間）** に、GitHub が自動で Wikipedia / Wikidata を確認し、
新しく追加されたソフトや修正された発売日などを取り込んで、サイトを更新します。

- 今すぐ更新したいとき：GitHub の「**▶ Actions**」→ 左の「**データを自動更新（Wikipedia / Wikidata）**」→「**Run workflow**」
- 自動更新を止めたいとき：同じ画面の右上「…」→「**Disable workflow**」

### 自動更新の安全装置

- **一度付いたソフトのページURL（例: `/games/fc-66/`）は変わりません。** タイトルの誤字が直されても、同じソフトと判断してURLを引き継ぎます（検索エンジンの評価が失われないようにするため）
- Wikipedia の一覧から消えたソフトも削除はせず、`"missingFromSource": true` という印を付けて残します
- データの書き方に間違いがあると公開処理が止まり、**サイトは前の正常な状態のまま**になります

## ソフト1本の情報を手で直す

### 1. 直したいソフトのIDを調べる

ソフトのページのURLの最後の部分がIDです。
例: `https://…/games/fc-66/` → ID は **`fc-66`**、機種は **`fc`**（ファミコン）

### 2. データファイルを開いて直す

機種ごとのファイル `data/games/機種ID.json`（例: `data/games/fc.json`）に、**1行に1本ずつ** 書かれています。

```json
{"id":"fc-66","title":"スーパーマリオブラザーズ","date":"1985-09-13","publishers":["任天堂"],"developers":["任天堂情報開発本部"],"genres":["action"],"note":"マリオ兄弟を操作するアクションゲーム","wiki":"スーパーマリオブラザーズ","wikidata":"Q11168","source":"ファミリーコンピュータのゲームタイトル一覧"},
```

| 項目 | 意味 | 書き方の例 |
| --- | --- | --- |
| `title` | タイトル | `"スーパーマリオブラザーズ"` |
| `date` | 日本での発売日 | `"1985-09-13"`（月までなら `"1985-09"`、年だけなら `"1985"`、未定なら `null`） |
| `publishers` | 発売元（複数可） | `["任天堂"]` |
| `developers` | 開発元（複数可） | `["任天堂情報開発本部"]` |
| `genres` | ジャンル（`data/genres.json` のID） | `["action", "rpg"]` |
| `price` | 発売時の価格（円） | `4900` |
| `cero` | CEROレーティング | `"A"` |
| `digitalOnly` | ダウンロード専用なら | `true` |
| `note` | 備考 | `"限定版あり"` |
| `description` | **紹介文（自由に書ける・自動更新で消えない）** | `"横スクロールアクションの金字塔。…"` |
| `lock` | **自動更新で上書きしない** | `true` |

> ⚠ 手で直した行には、最後に `"lock":true` を付けておきましょう。付けないと、次の自動更新で Wikipedia の内容に戻ることがあります。
> 例: `…,"source":"ファミリーコンピュータのゲームタイトル一覧","lock":true},`

### GitHub の画面で編集するには

- 小さいファイル：ファイルを開いて **鉛筆マーク（✏️）** → 編集 → 「**Commit changes**」
- 大きいファイル（Switch・PS4 など）：リポジトリのトップ画面でキーボードの **`.`（ピリオド）** を押すと、
  ブラウザ上で使える編集画面（github.dev）が開きます。`Ctrl + F` でIDを検索して直し、左の「ソース管理」から保存（Commit & Push）します

> 🙋 **一番かんたんなのは Claude に頼むこと** です。
> 例:「fc-66 の紹介文を『〇〇』にして」「PS5の『〇〇』の発売日を2026年12月3日に直して、自動更新で戻らないようにして」

## Wikipedia に載っていないソフトを追加する

該当する機種のファイルの最後の行の後ろに、1行追加します。

- `id` はその機種の **最大の番号＋1**（例: `fc.json` の最後が `fc-1053` なら `fc-1054`）
- `source` は `"manual"`（手入力の印。自動更新で消されません）

```json
{"id":"fc-1054","title":"〇〇〇〇","date":"1990-04-01","publishers":["〇〇"],"source":"manual"}
```

※ JSON では、行と行の間を `,`（カンマ）で区切ります。最後の行の後ろにはカンマを付けません。

## ゲーム機（ハード）を追加・修正する

`data/platforms.json` に機種ごとの情報（名前・発売日・価格・説明文・取り込み元の Wikipedia ページ名など）があります。
新しいゲーム機を追加したい場合は、Claude に「〇〇（ゲーム機名）を追加して」と頼んでください。
（Wikipedia に「〇〇のゲームタイトル一覧」があれば、ソフトも自動で取り込めます）

## パソコンでデータを更新する場合（上級者向け）

```bash
npm run data:import            # 全機種を取り込み（Wikipedia→Wikidata→検証）約10分
npm run data:wikipedia -- ps5  # 指定した機種だけ Wikipedia から取り込み
npm run data:wikidata -- ps5   # 指定した機種だけ Wikidata で補完
npm run data:validate          # データの書き方チェック
```

取得したページは `.cache` フォルダに1週間保存され、再実行時はそれを使います（Wikipedia への負荷を減らすため）。
